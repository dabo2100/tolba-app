# نظام المتابعة اللاحظي — نسخة تجريبية

تطبيق React + Vite لعرض بيانات مديرية الشؤون الصحية وإدخال بعض التعديلات. الواجهة بالعربية، والبيانات والحسابات الحالية **تجريبية** وليست متصلة بقاعدة بيانات.

## التشغيل

يتطلب Node.js المتوافق مع Vite 8 (الإصدار 20.19+ أو 22.12+). من مجلد المشروع:

```bash
npm install
npm run dev
```

افتح الرابط الذي يعرضه Vite (الإعداد الافتراضي `http://localhost:8443`). للتأكد من سلامة المشروع:

```bash
npx tsc --noEmit
npm run build
```

حسابات التجربة موجودة على شاشة الدخول: `admin` أو `diwan` أو `a1`–`a11` أو `h1`–`h18`، وكلمة المرور `1234`. **لا تستخدم هذه الحسابات لحماية بيانات حقيقية.**

## خريطة الملفات

- `src/App.tsx`: اختيار شاشة الدخول أو واجهة الصلاحية المناسبة فقط.
- `src/features/`: مكونات مستقلة حسب المجال (`auth`, `dashboard`, `directorate`, `diwan`, `administrations`, `hospitals`, `workforce`).
- `src/components/common/`: عناصر عرض ونماذج مشتركة.
- `src/domain/models.ts`: أنواع وكيانات البيانات، بدون أي اعتماد على React.
- `src/data/seed.ts`: البيانات الأولية للتجربة وبناء الحالة الابتدائية.
- `src/data/reference.ts`: تصنيفات وألوان وبيانات مرجعية تجريبية.
- `src/data/AppDataRepository.ts`: العقد غير المرتبط بمصدر تخزين بعينه.
- `src/data/MemoryAppDataRepository.ts`: تنفيذ مؤقت في الذاكرة؛ **التغييرات تضيع عند تحديث الصفحة**.
- `src/data/repository.ts`: المكان الوحيد لاختيار تنفيذ الـ Repository.
- `src/state/AppDataContext.tsx`: تحميل البيانات وإتاحتها للواجهة وتنفيذ العمليات عبر الـ Repository.

مسار البيانات: **Repository → Provider → Components**. المكونات لا تتصل مباشرةً بالبيانات الأولية أو بقاعدة البيانات. عمليات التعديل تستخدم IDs ثابتة، بينما اختيار الصف المعروض في بعض الشاشات لا يزال مبنيًا على ترتيب القوائم.

## النقل مستقبلًا إلى PostgreSQL

PostgreSQL لا يجب أن يتصل بالمتصفح مباشرةً. أضف Backend يوفر API آمنة، ونفّذ `AppDataRepository` في Adapter يستخدم `fetch`، ثم استبدل التنفيذ في `src/data/repository.ts`. يفضل أن يكون حفظ الديوان عملية واحدة على الخادم داخل transaction، وأن تحفظ عملية تعديل الجهة وسجل التغيير معًا. سيظل `src/domain/models.ts` هو عقد البيانات بين الطبقات (مع إضافة DTOs/validation عند ربط الـ API).

**قبل نقل البيانات الحقيقية:** نماذج التخصصات التفصيلية، تفاصيل الوحدات الصحية، طاقات الوحدات ونسب الإشغال ما زالت محسوبة/محلية بالواجهة وغير محفوظة؛ تحتاج جداول وواجهات CRUD خاصة بها. أيضًا يجب استبدال تسجيل الدخول التجريبي بمصادقة وصلاحيات على الخادم، وإضافة التحقق من المدخلات واختبارات للـ API. راجع `docs/data-model.md` لخطة الجداول والواجهات المقترحة.
